# Milestone Rubric — Checkpoint Tracking

Every weekly milestone below is **reviewed/approved as a pass/fail checkpoint** (does it meet the "real project" bar — real repo, real stakeholder, real evidence?) — the actual weighted **grade** is assigned holistically at the [Week 15 defense](../slides/Week-15-Defense.md) using the rubric at the bottom of this page. This page exists so instructors and teams can track, week by week, whether a team is on track for that final grade — not to assign separate points per week.

## Checkpoints by week

| Week | Deliverable | "Meets the bar" means |
|---|---|---|
| [2](../slides/Week-02-Initiation.md) | Real Project Charter | All required components filled with the team's real answers (not placeholder text); project qualifies as "real" per Week 1's rule |
| [3](../slides/Week-03-Scope-WBS.md) | Real WBS | Deliverable-oriented, satisfies the 100% rule, work packages sized to ~1-2 weeks each |
| [6](../slides/Week-06-Risk-Quality.md) | Risk Register update #1 | Contains risks that actually happened in Sprint 1 — not only hypothetical, generic risks |
| [7](../slides/Week-07-Resources-Team.md) | Sprint 1 Retrospective + Sprint 2 plan | Retro reflects what *actually* happened (specific, not generic); Sprint 2 plan incorporates what was learned |
| [11](../slides/Week-11-Change-Management.md) | Risk Register update #2 + real scope change handled | Register shows real evolution since Week 6; at least one real scope change was processed and recorded |
| [13](../slides/Week-13-Project-Closure.md) | Project closure | Real acceptance from the real stakeholder on the real deliverable; final (whole-project) retrospective run |

A checkpoint sent back for not meeting the bar should be resolved before the *next* checkpoint — don't let a gap compound to Week 14.

## Final grade — [Week 15](../slides/Week-15-Defense.md) defense rubric

| Component | Weight |
|---|---|
| **Project authenticity gate** — real repo/deliverable, real management event handled | Pass/fail gate — cap at 5/10 overall if not met |
| Plan completeness & feasibility (WBS, schedule, risk) | 25% |
| Methodology fit (Agile/Waterfall/Hybrid, justified) | 20% |
| Real execution evidence (commit/board history, real burndown/EVM) | 25% |
| AI usage in the management process, with concrete evidence | 15% |
| Presentation | 15% |

Each checkpoint above feeds directly into one or more of these components — e.g., Weeks 2-3 into "Plan completeness," Weeks 6/11 into "Real execution evidence," Week 13 into the authenticity gate.
